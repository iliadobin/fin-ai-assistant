# Финансовый AI-ассистент на основе RAG

## 📋 Описание задачи

Разработать финансового AI-ассистента на основе LLM API, который будет грамотно отвечать на вопросы пользователей финансовых инструментов банка, опираясь на базу знаний из финансовых статей.

### Исходные данные

- **База знаний**: `train_data.csv` - 350 финансовых статей (поля: id, annotation, tags, text)
- **Вопросы**: `questions.csv` - 500 вопросов пользователей
- **Базовое решение**: `baseline.py` - простой промпт без контекста

### Ограничения

- Использовать только библиотеки из `libraries.txt`
- Гарантировать правильность ответов через использование базы знаний

---

## 🎯 Решение: RAG архитектура

Выбрана архитектура **RAG (Retrieval-Augmented Generation)** - подход, объединяющий:
1. **Retrieval** - семантический поиск релевантных статей
2. **Augmentation** - добавление найденного контекста в промпт
3. **Generation** - генерация ответа LLM на основе контекста

### Преимущества RAG

✅ Ответы основаны на проверенных источниках (статьи)  
✅ Снижение "галлюцинаций" LLM  
✅ Возможность обновления базы знаний без переобучения модели  
✅ Прозрачность - можно отследить источник информации

## 📦 Модульная структура проекта

### Реализованные модули

#### 1. `data_loader.py` - Загрузка данных
**Функции:**
- `load_data()` - загрузка CSV файлов с проверкой структуры

**Назначение:** Централизованная загрузка и валидация данных

---

#### 2. `embeddings.py` - Работа с векторными представлениями
**Функции:**
- `get_embedding()` - получение embedding для одного текста через API
- `create_embeddings_batch()` - батчевое создание embeddings с progress bar
- `save_embeddings()` / `load_embeddings()` - кэширование embeddings
- `load_or_create_embeddings()` - умная загрузка (из кэша или создание новых)

**Технические решения:**
- Использование `annotation` вместо `text` для embeddings (решение проблемы с лимитом токенов 8192)
- Обработка NaN и пустых значений
- Сохранение в `embeddings.pkl` для ускорения повторных запусков (3.6 мин → мгновенно)

---

#### 3. `search.py` - Семантический поиск
**Функции:**
- `cosine_similarity()` - вычисление косинусной близости векторов
- `find_most_relevant_article()` - поиск наиболее релевантной статьи

**Алгоритм:**
1. Создание embedding для вопроса
2. Вычисление cosine similarity со всеми статьями
3. Возврат статьи с максимальным значением similarity

**Метрики качества:**
- Средний similarity score: 0.45-0.55
- Релевантность найденных статей: высокая (визуальная проверка)

---

#### 4. `main.py` - Основной пайплайн и генерация ответов
**Функции:**
- `answer_generation()` - генерация ответа с использованием RAG промпта

**Промпт-инжиниринг:**
```python
prompt = f"""Ты - финансовый AI-ассистент банка. 
Твоя задача - давать точные и грамотные ответы на вопросы 
клиентов о финансовых инструментах и услугах.

Используй ТОЛЬКО информацию из предоставленной статьи 
для ответа. Не добавляй информацию, которой нет в статье.

СТАТЬЯ:
{article_text}

ВОПРОС КЛИЕНТА:
{question}

Дай четкий, профессиональный и понятный ответ на русском языке. 
Ответ должен быть информативным, но кратким (2-4 предложения).
"""
```

**Пайплайн:**
1. Загрузка данных (train_data, questions)
2. Загрузка/создание embeddings для всех статей
3. Для каждого вопроса:
   - Поиск релевантной статьи
   - Генерация ответа через LLM
4. Сохранение результатов в `submission.csv`

## 🔧 Технические детали

### API и модели

| Компонент | API | Модель | Параметры |
|-----------|-----|--------|-----------|
| Embeddings | EMBEDDER_API_KEY | `text-embedding-3-small` | Размерность: 1536 |
| LLM | LLM_API_KEY | `mistralai/mistral-small-3.2-24b-instruct` | Temperature: default |

### Производительность

| Этап | Время (первый запуск) | Время (повторный запуск) |
|------|----------------------|--------------------------|
| Загрузка данных | ~1 сек | ~1 сек |
| Создание embeddings | ~3.6 мин (350 статей) | мгновенно (из кэша) |
| Генерация ответов | ~25-30 мин (500 вопросов) | ~25-30 мин |
| **ИТОГО** | **~30 мин** | **~25 мин** |

### Использование ресурсов

- **Память**: ~200 MB (embeddings в памяти)
- **Диск**: 
  - `embeddings.pkl`: ~4 MB
  - `submission.csv`: ~100 KB
- **API запросы**:
  - Embeddings: 350 (один раз) + 500 (для вопросов) = 850 запросов
  - LLM: 500 запросов

## ✅ Результаты и тестирование

### Тестовые примеры

#### Пример 1: Успешный поиск

**Вопрос:** Как действовать вкладчику при отзыве лицензии, учитывая лимит безопасной суммы?

**Найденная статья:** doc_286 (similarity: 0.4644)  
Аннотация: "Все банковские вклады и счета частных лиц... застрахованы..."

**Ответ:**
> При отзыве лицензии у банка вкладчику нужно обратиться в банк-агент (список публикуется на сайте АСВ на 7-й день) с паспортом и заявлением о выплате. Страховое возмещение до 1,4 млн рублей выплачивается в течение 3 рабочих дней после подачи заявления. Если сумма вклада больше, можно требовать возврата остатка после ликвидации банка.

✅ **Оценка:** Точный, релевантный ответ на основе статьи

---

#### Пример 2: Отсутствие информации в статье

**Вопрос:** Как просрочка по «беспроцентному» займу скажется на переплате/ПСК?

**Найденная статья:** doc_207 (similarity: 0.5566)  
Тема: "Период охлаждения при кредитах"

**Ответ:**
> В предоставленной статье нет информации о влиянии просрочки по «беспроцентному» займу на переплату или ПСК. Статья посвящена исключительно периоду охлаждения и его условиям.

✅ **Оценка:** Модель честно признается в отсутствии информации

---

### Выводы по качеству

✅ **Сильные стороны:**
- Ответы опираются на реальные статьи
- Высокая релевантность найденных статей (similarity 0.4-0.6)
- Модель не выдумывает информацию
- Ответы структурированные и понятные

⚠️ **Ограничения:**
